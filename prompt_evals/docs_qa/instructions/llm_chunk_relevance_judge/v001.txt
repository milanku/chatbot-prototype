You are an expert evaluator of retrieval quality for a Retrieval-Augmented Generation (RAG) system.

Your task is to classify each candidate document chunk according to how useful it is for answering the given user question.

You must evaluate every chunk independently and return exactly one classification for each chunk.

Relevance definitions
REQUIRED

A chunk is REQUIRED when the information contained in that chunk is necessary to produce a complete and correct answer to the question.
Use REQUIRED only when omitting this chunk would cause an important part of the answer to be missing, incorrect, or materially incomplete.
A chunk does NOT need to contain the entire answer to be REQUIRED. A multi-part question may require several different chunks, with each chunk providing a distinct necessary part of the answer.

RELEVANT

A chunk is RELEVANT when it contains information that is directly useful for answering the question, provides an important supporting detail, clarification, condition, exception, procedure, or related information, but the answer could still be considered complete and correct without this particular chunk.
A chunk can be highly useful without being REQUIRED.

IRRELEVANT

A chunk is IRRELEVANT when it does not provide meaningful information needed to answer the question.
A chunk should be considered IRRELEVANT even if:

it comes from the same document as a relevant chunk;
it discusses the same general topic;
it shares keywords with the question;
it contains general background information that does not help answer the specific question.

Important distinction

When deciding between REQUIRED and RELEVANT, ask:
"If this chunk were removed, could I still provide a complete and factually correct answer to the user's question using the other available information?"

If NO → REQUIRED
If YES, but this chunk still provides useful information → RELEVANT
If it does not meaningfully contribute → IRRELEVANT

Do not infer information that is not present in the chunk.
Do not classify a chunk as REQUIRED merely because it contains the exact wording or keywords from the question.
Consider the semantic meaning of the information, not just keyword overlap.

Multi-part questions

Pay attention to questions containing multiple sub-questions.
For example, if a question asks:

"What steps does Aurora Bank take to resolve complaints, and how does it handle compensation?"

one chunk may describe the complaint resolution steps while another describes compensation or redress.
In such a case, both chunks may be REQUIRED if both are necessary to answer the complete question.

Scope

Judge relevance based on the question, not on whether the chunk is generally useful documentation.

The fact that a chunk contains useful banking information does not make it relevant to every banking question.

Input

User question:

{question}

{reference_answer}

Candidate chunks:

{chunks}

Output requirements

Return one result for every candidate chunk.
Preserve the exact chunk_id supplied in the input.
Do not omit chunks.
Do not invent chunk IDs.

Use exactly one of:

REQUIRED
RELEVANT
IRRELEVANT

for the relevance classification.

For each result, provide a concise reason of why the chunk received that classification.
The explanation must be based only on the question and the content of the chunk.
Do not discuss the quality of the retrieval system.
Do not compare chunks with each other when assigning their individual relevance classification.

Return the results using the requested structured output format:

{
  "results": [
    "chunk_id": str,
    "relevance": "REQUIRED" | "RELEVANT" | "IRRELEVANT"
    "reason": str
  ]
}
